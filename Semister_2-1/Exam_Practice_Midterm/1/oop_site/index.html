2. self และ . (จุด) คืออะไร


self = "ตัวฉันเอง" — คือ object ที่กำลังทำงานอยู่ตอนนั้น

. (จุด) = "ของ" หรือ "ข้างใน" เช่น self.name = "name ของตัวฉัน", a.bark() = "สั่งให้ a เห่า"


ตอนเรียก a.bark() Python แอบส่ง a เข้าไปเป็น self ให้เอง เราเลยไม่ต้องใส่ในวงเล็บ

ที่ต้องเขียน self.name = name: ตัวซ้าย = ของที่เก็บไว้ใน object, ตัวขวา = ค่าที่ส่งเข้ามาเฉย ๆ (หายไปหลังฟังก์ชันจบ)




ลืมเขียน self. = ตัวแปรกลายเป็นของธรรมดา object จำไม่ได้ ← บั๊กยอดฮิตในข้อสอบ



3. _ หน้าชื่อ และ @property


self._radius — เครื่องหมาย _ หน้าชื่อ คือ ข้อตกลง ว่า "ข้างในนะ อย่าแตะจากข้างนอก" (Python ไม่ได้ล็อกจริง แต่ถ้าแตะเท่ากับผิดมารยาท)


@property = ทำให้ฟังก์ชันถูกเรียกเหมือน ตัวแปร (ไม่ต้องใส่วงเล็บ) และ ทำให้ อ่านได้อย่างเดียว


ตอบคำถามเรื่อง "leak": จริง ๆ ตรงข้ามเลย! ไม่ได้ปล่อยให้รั่ว แต่เป็น "หน้าต่างกระจก" — ให้ดู (ball.radius) แต่ไม่ให้แก้ (ball.radius = 5 จะ error)

ชื่อฟังก์ชัน radius (ไม่มี _) = ชื่อสาธารณะที่คนนอกใช้ / ตัวเก็บจริง _radius (มี _) = ของส่วนตัวข้างใน ชื่อต้องต่างกัน ไม่งั้นวนไม่รู้จบ

4. Encapsulation (การห่อหุ้ม)


ความหมาย: เอา ข้อมูล กับ ฟังก์ชันที่ใช้ข้อมูลนั้น มาห่อไว้ใน class เดียวกัน แล้ว ซ่อนข้อมูล ไว้ข้างใน ให้คนนอกเข้าถึงผ่าน "ประตู" (method / property) เท่านั้น

เหมือน: เครื่อง ATM — คุณกดปุ่มได้ แต่เปิดตู้ไปหยิบเงินเองไม่ได้

ทำไมต้องมี: กันคนแก้ค่าผิด ๆ (เช่น ยอดเงินติดลบ) และถ้าแก้โค้ดข้างใน คนนอกไม่ต้องแก้ตาม

ทำยังไงใน Python: (1) ข้อมูลใช้ชื่อมี _ (2) เปิดประตูด้วย @property หรือ method





5. Inheritance: class BouncingBall(Ball)


วงเล็บหลังชื่อ class = "พ่อแม่" (parent class) อ่านว่า "BouncingBall เป็นลูกของ Ball" → ได้ทุกอย่างของ Ball มาฟรี (draw, radius, ...) แล้วเพิ่มหรือแก้เฉพาะที่ต่าง (เช่น move)

ทำไม class Ball: ไม่มีวงเล็บ? เพราะ Ball เป็น class ต้นตระกูล ไม่มีพ่อแม่ (จริง ๆ Python ถือว่าเป็นลูกของ object อัตโนมัติ — class Ball: กับ class Ball(object): เหมือนกัน)





6. super()


super() = "ตัวแทนพ่อแม่" — ใช้เรียก method ของ parent จากใน child

super().__init__(...) = "พ่อ/แม่ช่วยตั้งค่าของที่เป็นของพ่อแม่ให้หน่อย" (เช่น _center_x, _radius ที่ Ball.__init__ เป็นคนสร้าง) แล้วลูกค่อยตั้งค่าของตัวเองต่อ

ทำไมต้อง .__init__ ต่อท้าย? super() เฉย ๆ แค่ได้ "ตัวแทน" มา ต้องบอกว่าจะให้เรียก method ไหน — ตรงนี้ต้องการ constructor เลยเป็น __init__ (จะ super().move() ก็ได้)

ทำไมมักไว้บรรทัดแรก? ไม่ได้บังคับ แต่ควร เพราะโค้ดลูกมักใช้ของที่พ่อแม่สร้าง ถ้ายังไม่เรียก ของพวกนั้นยังไม่เกิด

สำคัญ: ใน super().__init__(...) ไม่ต้องใส่ self และต้องส่ง argument ตามที่ Ball.__init__ ต้องการให้ครบ
